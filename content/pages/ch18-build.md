In this tutorial, the dual mode records a movie. The movie shows what the screen shows: one camera fills the frame, and the other camera is a small picture in a corner. A tap on the preview exchanges the two pictures on the screen and in the recording. The record button and the recording time of the video mode come back for the dual mode.

You add four files to the `Capture` group: `MovieRecorder.swift`, which writes a movie file with an [`AVAssetWriter`](https://developer.apple.com/documentation/avfoundation/avassetwriter); `PiPMixer.metal`, a compute kernel that draws the small picture into the full picture; `PiPVideoMixer.swift`, which runs the kernel; and `DualRecorder.swift`, which receives the frames of the outputs and connects the three parts. You also add approximately 150 lines to nine files that you know from the earlier chapters.

This chapter is a part of "Beyond the sample". The code is not in the Apple sample. The design follows the Apple sample [AVMultiCamPiP](https://developer.apple.com/documentation/avfoundation/avmulticampip-capturing-from-multiple-cameras), which has a mixer and a recorder of the same shape. Read [Concepts: record picture in picture](ch18-concepts.md) first if you want the background for each step.

> [!IMPORTANT]
> The test for this tutorial ran in the iPhone 18 Pro simulator (iOS 27.0) with SimCam. There, a recording of 10.8 seconds produced a movie of 640 by 480 pixels in the Photos library, with the small picture at the top left. The movie had no audio track, because the simulator reports audio settings with a sample rate of 0. Nobody ran this chapter on a real iPhone. So the audio track, the HEVC compression settings, and the costs of the three outputs are not verified on hardware.

The four new files need one change in the Xcode interface. The capture extension from chapter 13 compiles `CaptureService.swift`, which uses `MultiCamCapture`, which uses the new types. So the four files must also belong to the extension target, as the two files of chapter 17 do. Xcode writes this to the project file, `AVCam.xcodeproj/project.pbxproj`. You do not edit this file by hand, so no step shows it.

## Write the movie recorder

In chapter 8, `AVCaptureMovieFileOutput` compressed the frames and wrote the file by itself. The mixed frames of the dual mode exist in no connection, so the app writes the file itself. In this section, you write `MovieRecorder`, a small class around an `AVAssetWriter` with a video input and an optional audio input. Nothing uses the class yet, so the section ends with a build.

### Step
Create a new Swift file with the name `MovieRecorder.swift` in the `Capture` group, and replace its contents.

The writer gets a temporary URL from `URL.movieFileURL`, the extension from chapter 8, and the QuickTime file type. Each track is an [`AVAssetWriterInput`](https://developer.apple.com/documentation/avfoundation/avassetwriterinput) with compression settings from the caller. [`expectsMediaDataInRealTime`](https://developer.apple.com/documentation/avfoundation/avassetwriterinput/expectsmediadatainrealtime) tells the writer that the samples come from live capture, so it must not wait for a full buffer. The audio input exists only when the caller gives audio settings.

```swift file=AVCam/Capture/MovieRecorder.swift new
/*
See the LICENSE.txt file for this sample's licensing information.

Abstract:
An object that writes video and audio sample buffers to a movie file.
*/

import AVFoundation

/// An object that writes sample buffers to a QuickTime movie file with an asset writer.
///
/// `AVCaptureMovieFileOutput` does this work by itself for one camera. For frames that the app makes
/// itself, the app has to write the file. `DualRecorder` calls this object on the data output queue.
final class MovieRecorder {
    
    private let writer: AVAssetWriter
    private let videoInput: AVAssetWriterInput
    private let audioInput: AVAssetWriterInput?
    
    /// The location of the movie file.
    var outputURL: URL { writer.outputURL }
    
    /// Creates a recorder that writes to a new temporary file.
    ///
    /// - Parameters:
    ///   - videoSettings: The compression settings for the video track, from the video data output.
    ///   - audioSettings: The compression settings for the audio track, or `nil` for a movie without sound.
    init(videoSettings: [String: Any], audioSettings: [String: Any]?) throws {
        writer = try AVAssetWriter(outputURL: .movieFileURL, fileType: .mov)
        
        // The inputs receive the frames in real time, so the writer must not wait for a full buffer.
        videoInput = AVAssetWriterInput(mediaType: .video, outputSettings: videoSettings)
        videoInput.expectsMediaDataInRealTime = true
        writer.add(videoInput)
        
        if let audioSettings {
            let input = AVAssetWriterInput(mediaType: .audio, outputSettings: audioSettings)
            input.expectsMediaDataInRealTime = true
            writer.add(input)
            audioInput = input
        } else {
            audioInput = nil
        }
    }
}
```

### Step
Below the initializer, add the `append(videoSampleBuffer:)` method. The first video frame starts the file and sets its time zero.

`startWriting()` opens the file one time, when the writer is still in the `unknown` state. Then [`startSession(atSourceTime:)`](https://developer.apple.com/documentation/avfoundation/avassetwriter/startsession(atsourcetime:)) takes the time stamp of the first frame as the time zero of the movie. With a time zero of 0, the movie would start with a long empty gap. Before the `append`, the code checks [`isReadyForMoreMediaData`](https://developer.apple.com/documentation/avfoundation/avassetwriterinput/isreadyformoremediadata): an `append` on an input that is not ready raises an exception, and in real time a dropped frame is the better choice.

## Write the Metal mixer

The mixer draws the small picture into the full picture. It does this on the GPU with a compute kernel: a function that runs one time for each pixel of the output. In this section, you write the kernel in the Metal shading language, and then the Swift class that gives the kernel its textures and runs it. Two files, one job.

### Step
Create a new Metal file with the name `PiPMixer.metal` in the `Capture` group, and replace its contents with the parameters and the sampler.

Use the Metal File template. `MixerParameters` is the structure that the Swift code fills: the position and the size of the small picture, in pixels of the output. The Swift copy must have the same layout. The sampler scales the small picture down with linear filtering, and it reads the texture in pixel coordinates. The [Metal Shading Language Specification](https://developer.apple.com/metal/Metal-Shading-Language-Specification.pdf) describes both.

```objc file=AVCam/Capture/PiPMixer.metal new
/*
See the LICENSE.txt file for this sample's licensing information.

Abstract:
A compute kernel that draws a small picture into a full-size picture.
*/

#include <metal_stdlib>
using namespace metal;

/// The position and size of the small picture, in pixels of the output texture.
struct MixerParameters {
    float2 smallPicturePosition;
    float2 smallPictureSize;
};

/// A sampler that scales the small picture with linear filtering.
constant sampler linearSampler(filter::linear, coord::pixel, address::clamp_to_edge);
```

### Step
Below the sampler, add the kernel `pictureInPictureMixer`. It writes one output pixel for each thread.

The kernel gets three textures and the parameters. `thread_position_in_grid` is the pixel that this thread writes. The GPU runs the kernel in groups of threads, and the last groups can reach beyond the edge of the texture, so the first test returns for a position outside the output. Inside the frame of the small picture, the kernel maps the output pixel to a pixel of the small picture and lets the sampler scale it down. Everywhere else, it copies the pixel of the full picture.

```objc file=AVCam/Capture/PiPMixer.metal highlight=3-29
constant sampler linearSampler(filter::linear, coord::pixel, address::clamp_to_edge);

/// Writes one output pixel: from the small picture inside its frame, from the full picture elsewhere.
kernel void pictureInPictureMixer(texture2d<half, access::read> fullPicture [[ texture(0) ]],
                                  texture2d<half, access::sample> smallPicture [[ texture(1) ]],
                                  texture2d<half, access::write> output [[ texture(2) ]],
                                  const device MixerParameters& parameters [[ buffer(0) ]],
                                  uint2 position [[ thread_position_in_grid ]]) {
    // Stay inside the output texture; the grid can be larger than the texture.
    if (position.x >= output.get_width() || position.y >= output.get_height()) {
        return;
    }
    
    uint2 origin = uint2(parameters.smallPicturePosition);
    uint2 size = uint2(parameters.smallPictureSize);
    bool insideSmallPicture = position.x >= origin.x && position.y >= origin.y &&
                              position.x < origin.x + size.x && position.y < origin.y + size.y;
    
    half4 color;
    if (insideSmallPicture) {
        // Map the output pixel to a pixel of the small picture, which the sampler scales down.
        float2 scale = float2(smallPicture.get_width(), smallPicture.get_height()) / parameters.smallPictureSize;
        float2 source = float2(position - origin) * scale;
        color = smallPicture.sample(linearSampler, source + 0.5);
    } else {
        color = fullPicture.read(position);
    }
    output.write(color, position);
}
```

### Step
Create a new Swift file with the name `PiPVideoMixer.swift` in the `Capture` group, and replace its contents.

The Swift `MixerParameters` has the same layout as the Metal structure: two pairs of 32-bit floats. `smallPictureFrame` is the frame of the small picture as a part of the full picture, from 0 to 1. The initializer compiles the kernel one time: [`makeDefaultLibrary()`](https://developer.apple.com/documentation/metal/mtldevice/makedefaultlibrary()) loads every `.metal` file of the target, and the [`MTLComputePipelineState`](https://developer.apple.com/documentation/metal/mtlcomputepipelinestate) is the compiled kernel, ready to run. The pool, the texture cache, and the output format come later, because they depend on the size of the frames.

```swift file=AVCam/Capture/PiPVideoMixer.swift new
/*
See the LICENSE.txt file for this sample's licensing information.

Abstract:
An object that draws the frames of two cameras into one frame with Metal.
*/

import CoreMedia
import CoreVideo
import Metal

/// An object that draws a small picture from one camera into the full picture of the other camera.
///
/// The mixer runs a Metal compute kernel for each frame. `DualRecorder` calls it on the data output queue.
final class PiPVideoMixer {
    
    /// The parameters that the kernel reads. The layout must match the `MixerParameters` struct in the shader.
    private struct MixerParameters {
        var smallPicturePosition: SIMD2<Float>
        var smallPictureSize: SIMD2<Float>
    }
    
    /// The frame of the small picture, as a part of the full picture (0 to 1 in each direction).
    var smallPictureFrame = CGRect(x: 0.04, y: 0.03, width: 0.3, height: 0.3)
    
    /// A Boolean value that indicates whether the mixer has a buffer pool for the current frame size.
    private(set) var isPrepared = false
    
    /// The format of the frames that the mixer produces.
    private(set) var outputFormatDescription: CMFormatDescription?
    
    private let device = MTLCreateSystemDefaultDevice()
    private var commandQueue: MTLCommandQueue?
    private var pipelineState: MTLComputePipelineState?
    private var textureCache: CVMetalTextureCache?
    private var outputPool: CVPixelBufferPool?
    
    init() {
        // Compile the kernel one time. The default library contains every `.metal` file of the target.
        guard let device, let library = device.makeDefaultLibrary(),
              let function = library.makeFunction(name: "pictureInPictureMixer") else { return }
        commandQueue = device.makeCommandQueue()
        pipelineState = try? device.makeComputePipelineState(function: function)
    }
}
```

### Step
Below the initializer, add the `prepare(with:)` method. It creates a pool of output buffers with the size of the input frames.

A [`CVPixelBufferPool`](https://developer.apple.com/documentation/corevideo/cvpixelbufferpool) reuses buffers that the writer has released, so the app allocates no memory for each frame. The pool makes BGRA buffers, the format that the kernel writes. The IOSurface property lets the GPU and the asset writer share a buffer without a copy. The method ends after the pool for now; the next step completes it.

```swift file=AVCam/Capture/PiPVideoMixer.swift highlight=3-22

    // MARK: - Preparation
    
    /// Creates a pixel buffer pool and a texture cache for frames of the given format.
    func prepare(with formatDescription: CMFormatDescription) {
        reset()
        guard let device else { return }
        
        // The output frames have the size and the pixel format of the input frames.
        let dimensions = CMVideoFormatDescriptionGetDimensions(formatDescription)
        let attributes: [String: Any] = [
            kCVPixelBufferPixelFormatTypeKey as String: kCVPixelFormatType_32BGRA,
            kCVPixelBufferWidthKey as String: Int(dimensions.width),
            kCVPixelBufferHeightKey as String: Int(dimensions.height),
            // An IOSurface lets Metal and the asset writer share the buffer without a copy.
            kCVPixelBufferIOSurfacePropertiesKey as String: [:]
        ]
        var pool: CVPixelBufferPool?
        guard CVPixelBufferPoolCreate(nil, nil, attributes as CFDictionary, &pool) == kCVReturnSuccess, let pool else { return }
        outputPool = pool
    }
}
```

### Step

The asset writer needs a format description for each mixed frame. The simplest source is a first buffer from the pool. A [`CVMetalTextureCache`](https://developer.apple.com/documentation/corevideo/cvmetaltexturecache) turns a pixel buffer into a Metal texture that shares its memory. `reset()` discards all three, so that a new frame size gets a new pool.

### Step

The method `makeTexture(from:)` comes in a later step. The parameters convert `smallPictureFrame` from parts of the picture to pixels of the output, because the kernel works in pixels. The method ends after the parameters for now.


### Step
Complete `mix(fullPicture:smallPicture:)` with the encoder, the thread groups, and the wait for the GPU.

An [`MTLComputeCommandEncoder`](https://developer.apple.com/documentation/metal/mtlcomputecommandencoder) gets the pipeline state, the three textures at the indexes of the kernel, and the parameters as bytes. The pipeline state tells the best width of a thread group and the largest group size; the division rounds up, so that the groups cover every pixel. `commit()` sends the work to the GPU, and `waitUntilCompleted()` blocks until the frame is complete. A production app would use a completion handler and more buffers instead; the wait is simple and correct.

```swift file=AVCam/Capture/PiPVideoMixer.swift highlight=3-25
                                    Float(smallPictureFrame.height) * Float(outputTexture.height)))
        
        // Encode one run of the kernel over every pixel of the output.
        guard let commandBuffer = commandQueue.makeCommandBuffer(),
              let encoder = commandBuffer.makeComputeCommandEncoder() else { return nil }
        encoder.setComputePipelineState(pipelineState)
        encoder.setTexture(fullTexture, index: 0)
        encoder.setTexture(smallTexture, index: 1)
        encoder.setTexture(outputTexture, index: 2)
        encoder.setBytes(&parameters, length: MemoryLayout<MixerParameters>.size, index: 0)
        
        // Split the output into thread groups that fit the GPU.
        let width = pipelineState.threadExecutionWidth
        let height = pipelineState.maxTotalThreadsPerThreadgroup / width
        let threadsPerGroup = MTLSize(width: width, height: height, depth: 1)
        let groups = MTLSize(width: (outputTexture.width + width - 1) / width,
                             height: (outputTexture.height + height - 1) / height,
                             depth: 1)
        encoder.dispatchThreadgroups(groups, threadsPerThreadgroup: threadsPerGroup)
        encoder.endEncoding()
        
        // Wait for the GPU, so that the frame is complete when the writer reads it.
        commandBuffer.commit()
        commandBuffer.waitUntilCompleted()
        return output
    }
```

## Write the dual recorder

The dual recorder is the delegate of the three data outputs. It receives each frame and each block of audio samples on one serial queue, sorts the frames by camera, mixes the two pictures, and gives the result to the movie recorder. In this section, you write the class. The session gets its outputs in the next section.

### Step
Create a new Swift file with the name `DualRecorder.swift` in the `Capture` group, and replace its contents.

The class adopts the two delegate protocols, [`AVCaptureVideoDataOutputSampleBufferDelegate`](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutputsamplebufferdelegate) and [`AVCaptureAudioDataOutputSampleBufferDelegate`](https://developer.apple.com/documentation/avfoundation/avcaptureaudiodataoutputsamplebufferdelegate), which need an `NSObject`. `captureActivity` is published, like in `MovieCapture` from chapter 8, so the capture service can show the recording time. `dataOutputQueue` is the serial queue of all three outputs: one queue means that no two delegate calls run at the same time, so the class needs no lock. The recorder keeps the three outputs, because the delegate method tells only the output that a frame comes from.

```swift file=AVCam/Capture/DualRecorder.swift new
/*
See the LICENSE.txt file for this sample's licensing information.

Abstract:
An object that receives the frames of two cameras, mixes them, and records them.
*/

import AVFoundation
import Combine

/// An object that receives the sample buffers of the dual mode, mixes the two pictures, and records a movie.
///
/// The data outputs call this object on their queue, `dataOutputQueue`. `MultiCamCapture` calls
/// `startRecording()` and `stopRecording()` on the same queue, so no lock is needed.
final class DualRecorder: NSObject, AVCaptureVideoDataOutputSampleBufferDelegate, AVCaptureAudioDataOutputSampleBufferDelegate {
    
    /// A value that indicates the current state of movie capture.
    @Published private(set) var captureActivity: CaptureActivity = .idle
    
    /// The serial queue on which the outputs deliver their sample buffers.
    let dataOutputQueue = DispatchQueue(label: "com.karolkakol.AVCam.dataOutputQueue")
    
    /// The camera that the small picture shows. The other camera fills the frame.
    var smallPicture = AVCaptureDevice.Position.front
    
    // The outputs, so that the recorder knows which camera a frame comes from.
    private let backOutput: AVCaptureVideoDataOutput
    private let frontOutput: AVCaptureVideoDataOutput
    private let audioOutput: AVCaptureAudioDataOutput?
    
    private let mixer = PiPVideoMixer()
    private var recorder: MovieRecorder?
    
    // The last frame of the camera in the small picture.
    private var latestSmallPictureFrame: CMSampleBuffer?
    // The time of the first recorded frame, to compute the recording time.
    private var recordingStartTime: CMTime?
    // The last recording time that the recorder reported.
    private var reportedDuration = TimeInterval.zero
    
    init(backOutput: AVCaptureVideoDataOutput, frontOutput: AVCaptureVideoDataOutput, audioOutput: AVCaptureAudioDataOutput?) {
        self.backOutput = backOutput
        self.frontOutput = frontOutput
        self.audioOutput = audioOutput
    }
    
    /// A Boolean value that indicates whether a recording is in progress.
    var isRecording: Bool { recorder != nil }
}
```

### Step
Below `isRecording`, add the `startRecording()` method. It creates a movie recorder with the settings that the outputs recommend.

[`recommendedVideoSettingsForAssetWriter(writingTo:)`](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutput/recommendedvideosettingsforassetwriter(writingto:)) returns compression settings that fit the format of the output and the file type. The audio settings have a trap: [`recommendedAudioSettingsForAssetWriter(writingTo:)`](https://developer.apple.com/documentation/avfoundation/avcaptureaudiodataoutput/recommendedaudiosettingsforassetwriter(writingto:)) is valid only after the microphone delivered samples. In the simulator, the sample rate is 0, and `AVAssetWriterInput` raises an exception for that value. The first version of this chapter crashed here. The guard records without sound in that case.

```swift file=AVCam/Capture/DualRecorder.swift highlight=3-21
    var isRecording: Bool { recorder != nil }
    
    // MARK: - Recording
    
    /// Starts a recording with the compression settings that the outputs recommend.
    func startRecording() throws {
        guard recorder == nil else { return }
        guard let videoSettings = backOutput.recommendedVideoSettingsForAssetWriter(writingTo: .mov) else {
            throw MovieCaptureError.notRecording
        }
        // The audio settings are valid only after the microphone delivered samples. Without a
        // sample rate the writer raises an exception, so the movie gets no sound in that case.
        var audioSettings = audioOutput?.recommendedAudioSettingsForAssetWriter(writingTo: .mov)
        if (audioSettings?[AVSampleRateKey] as? Double ?? 0) <= 0 {
            audioSettings = nil
        }
        recorder = try MovieRecorder(videoSettings: videoSettings, audioSettings: audioSettings)
        recordingStartTime = nil
        reportedDuration = .zero
        captureActivity = .movieCapture()
    }
}
```

### Step
Below `startRecording()`, add the `stopRecording()` method. It gives up the movie recorder and returns it.

The method does not finish the file. It detaches: after the `defer` block, `recorder` is `nil`, and no frame reaches the movie recorder. The caller runs this method on the data output queue, so the detach happens between two frames. Then the caller can finish the file on any queue, with no frame in flight.

### Step
Below `stopRecording()`, add the delegate method `captureOutput(_:didOutput:from:)`. It sorts each sample buffer by its output.

Both delegate protocols use the same method, [`captureOutput(_:didOutput:from:)`](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutputsamplebufferdelegate/captureoutput(_:didoutput:from:)). Audio samples go to the movie recorder at once. A video frame is the small picture when its output and `smallPicture` name the same camera. The recorder stores the latest small picture frame and processes each full picture frame, so the full picture sets the frame rate and the time stamps of the movie.

```swift file=AVCam/CameraView.swift highlight=8-9,24-25
                            // Play a sound when capturing by clicking an AirPods stem. Play it before
                            // the capture, so that the person hears it at the moment of the click.
                            if event.shouldPlaySound {
                                event.play(sound)
                            }
                            switch camera.captureMode {
                            case .photo:
                                // Capture a photo when pressing a hardware button.
                                await camera.capturePhoto()
                            case .video:
                                // Toggle video recording when pressing a hardware button.
                                await camera.toggleRecording()
                            case .dual:
                                // The dual mode records a movie, like the video mode.
                                await camera.toggleRecording()
                            }
```

## Check your understanding

### The video mode records with `AVCaptureMovieFileOutput`. Why does the dual mode need `MovieRecorder` with an `AVAssetWriter` instead?

- [ ] A multi-camera session accepts no movie file output.
  > A multi-camera session accepts the same outputs as a plain session. The reason is in the frames, not in the session.
- [x] A movie file output records the frames of one connection, and the mixed frames of the dual mode exist in no connection. The app makes them, so the app must write them.
  > Correct. The data outputs give the app the frames of each camera, the mixer makes a new frame, and the asset writer writes it to a file. The video mode keeps its movie file output.
- [ ] A movie file output cannot write a QuickTime file with an audio track.
  > It can, and it did in chapter 8. The movie file output is limited to the frames that a connection delivers.

### In the simulator, the recorded movie has no audio track. Which line is the reason, and why is it there?

- [ ] `let microphone = try? deviceLookup.defaultMic`. The simulator has no microphone, so `defaultMic` throws.
  > The simulator has a microphone input, and the session connects it. The audio output delivers nothing, but the input exists.
- [x] `if (audioSettings?[AVSampleRateKey] as? Double ?? 0) <= 0 { audioSettings = nil }`. The recommended audio settings have a sample rate of 0 before the microphone delivered samples, and an `AVAssetWriterInput` with that value raises an exception.
  > Correct. The first version of this chapter crashed at the start of each recording. The guard records without sound instead. On a real iPhone, the microphone delivers samples at once, so the settings are valid there, but nobody verified that.
- [ ] `audioOutput.setSampleBufferDelegate(recorder, queue: recorder.dataOutputQueue)`. The audio output needs its own queue.
  > One serial queue for all outputs is correct. It is the reason why the recorder needs no lock.

### `MultiCamCapture.stopRecording()` first calls `recorder.stopRecording()` with `sync` on the data output queue, and then `movieRecorder.finish()`. Why this order?

- [ ] `finish()` must run on the data output queue, and `sync` puts it there.
  > `finish()` runs on the capture actor, after the `sync` block. The `sync` block only detaches the movie recorder.
- [x] The detach happens between two frames on the data output queue, so no frame reaches the writer after it. Then `finish()` can close the file with no frame in flight.
  > Correct. A frame that arrives during `finishWriting()` would be an error. The detach first, then the finish, makes that impossible.
- [ ] `recorder.stopRecording()` writes the index of the file, and `finish()` only returns the URL.
  > `recorder.stopRecording()` writes nothing. It sets `recorder` to `nil` and returns the movie recorder. `finish()` closes the inputs and waits for `finishWriting()`.
