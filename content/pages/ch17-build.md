In this tutorial, you add a third capture mode to the app. In the dual mode, the back camera fills the screen, and the front camera is a small picture in a corner. A tap exchanges the two pictures. The mode captures nothing yet. The next chapter adds the capture.

You add two files: `MultiCamCapture.swift`, which owns an [`AVCaptureMultiCamSession`](https://developer.apple.com/documentation/avfoundation/avcapturemulticamsession), and `DualCameraPreview.swift`, which shows the two previews. You also add approximately 170 lines to twelve files that you know from the earlier chapters.

This chapter is a part of "Beyond the sample". The code is not in the Apple sample. The connection code follows the Apple sample [AVMultiCamPiP](https://developer.apple.com/documentation/avfoundation/avmulticampip-capturing-from-multiple-cameras), changed to fit this app. Read [Concepts: two cameras at once](ch17-concepts.md) first if you want the background for each step.

> [!IMPORTANT]
> The test for this tutorial ran in the iPhone 18 Pro simulator (iOS 27.0) with SimCam. There, the two simulated cameras ran at the same time. The simulator reports a cost of 0 for each configuration, and nobody ran this chapter on a real iPhone. So the format selection and the two costs are not verified on hardware.

The two new files need one change in the Xcode interface. The capture extension from chapter 13 compiles `CaptureService.swift` and `CameraView.swift`, and these files use the new types. So the new files must also belong to the extension target, like the 28 files from chapter 13. Xcode writes this to the project file, `AVCam.xcodeproj/project.pbxproj`. You do not edit this file by hand, so no step shows it.

## Create the multi-camera session

An `AVCaptureMultiCamSession` runs two cameras. In this section, you write the `MultiCamCapture` class, which owns the session, adds the two cameras, and connects each camera to its own preview layer. The class is a plain class, like `PhotoCapture` and `MovieCapture`. The capture service owns it and calls it on its own actor.

A new file in the `AVCam` group belongs only to the app target. That is enough for this section, because nothing uses the class yet. You add the file to the capture extension in the next section.

### Step
Create a new Swift file with the name `MultiCamCapture.swift` in the `Capture` group, and replace its contents.

The static `isSupported` property reads [`isMultiCamSupported`](https://developer.apple.com/documentation/avfoundation/avcapturemulticamsession/ismulticamsupported), which is `true` on a device with the A12 chip or a later one. The session is a stored property, like the single session of the capture service. The width limit keeps the hardware cost low: two large formats cost more than the hardware can give.

```swift file=AVCam/Capture/MultiCamCapture.swift new
/*
See the LICENSE.txt file for this sample's licensing information.

Abstract:
An object that manages a multi-camera session to capture from two cameras at the same time.
*/

import AVFoundation

/// An object that manages a multi-camera session, which captures from the back camera and the front camera at the same time.
///
/// `CaptureService` owns this object and calls it on the session queue. The multi-camera
/// session is a second session; the app runs it only in the dual capture mode.
final class MultiCamCapture {
    
    /// A Boolean value that indicates whether the device can capture from two cameras at the same time.
    static var isSupported: Bool {
        AVCaptureMultiCamSession.isMultiCamSupported
    }
    
    /// The multi-camera session.
    let session = AVCaptureMultiCamSession()
    
    // The inputs for the two cameras.
    private var backInput: AVCaptureDeviceInput?
    private var frontInput: AVCaptureDeviceInput?
    
    // A Boolean value that indicates whether the session has its inputs and connections.
    private(set) var isConfigured = false
    
    // The largest width of a camera format that the dual mode uses. Two large formats cost more than the hardware can give.
    private let maxFormatWidth: Int32 = 1920
}
```

### Step
Below the `maxFormatWidth` property, add the `configure(backCamera:frontCamera:backPreview:frontPreview:)` method. It adds the two cameras in one configuration.

The method runs one time. `beginConfiguration()` and `commitConfiguration()` make the two additions one atomic change, as in chapter 1. The `addCamera(_:previewLayer:)` method does not exist yet. You write it in the next three steps.

```swift file=AVCam/Capture/MultiCamCapture.swift highlight=4-20
    // The largest width of a camera format that the dual mode uses. Two large formats cost more than the hardware can give.
    private let maxFormatWidth: Int32 = 1920
    
    // MARK: - Configuration
    
    /// Adds the two cameras to the session and connects each one to its own preview layer.
    func configure(backCamera: AVCaptureDevice, frontCamera: AVCaptureDevice,
                   backPreview: AVCaptureVideoPreviewLayer, frontPreview: AVCaptureVideoPreviewLayer) throws {
        // Configure the session one time only.
        guard !isConfigured else { return }
        
        // Change the configuration atomically.
        session.beginConfiguration()
        defer { session.commitConfiguration() }
        
        backInput = try addCamera(backCamera, previewLayer: backPreview)
        frontInput = try addCamera(frontCamera, previewLayer: frontPreview)
        
        isConfigured = true
    }
}
```

### Step
Below `configure`, add the `addCamera(_:previewLayer:)` method. It selects a format, creates an input, and adds the input with no connections.

[`addInputWithNoConnections(_:)`](https://developer.apple.com/documentation/avfoundation/avcapturesession/addinputwithnoconnections(_:)) is the key call of this chapter. A plain `addInput(_:)` connects the camera to every output and to the preview layer. With two cameras, each camera would connect to each output. The format selection comes first, because the session accepts only a camera with a multi-camera format. The method `selectMultiCamFormat(for:)` comes in a later step.

```swift file=AVCam/Capture/MultiCamCapture.swift highlight=4-17
        isConfigured = true
    }
    
    // Adds an input for a camera and a connection from the camera to a preview layer.
    private func addCamera(_ device: AVCaptureDevice, previewLayer: AVCaptureVideoPreviewLayer) throws -> AVCaptureDeviceInput {
        // Select a format that works in a multi-camera session before the camera joins it.
        try selectMultiCamFormat(for: device)
        
        let input = try AVCaptureDeviceInput(device: device)
        guard session.canAddInput(input) else {
            throw CameraError.addInputFailed
        }
        // Add the input without connections. The session must not connect the camera to every output.
        session.addInputWithNoConnections(input)
        
        return input
    }
}
```

### Step
Before the `return` statement, get the video port, give the preview layer the session with no connection, and connect the port to the layer.

An input has one port for each stream that it supplies. `ports(for:sourceDeviceType:sourceDevicePosition:)` returns the ports for one media type, device type, and position. [`setSessionWithNoConnection(_:)`](https://developer.apple.com/documentation/avfoundation/avcapturevideopreviewlayer/setsessionwithnoconnection(_:)) tells the layer its session but makes no connection. Then [`AVCaptureConnection(inputPort:videoPreviewLayer:)`](https://developer.apple.com/documentation/avfoundation/avcaptureconnection/init(inputport:videopreviewlayer:)) links this camera, and only this camera, to the layer.

```swift file=AVCam/Capture/MultiCamCapture.swift highlight=4-15
        // Add the input without connections. The session must not connect the camera to every output.
        session.addInputWithNoConnections(input)
        
        // The video port of the input carries the frames of this camera.
        guard let videoPort = input.ports(for: .video, sourceDeviceType: device.deviceType, sourceDevicePosition: device.position).first else {
            throw CameraError.addInputFailed
        }
        
        // Give the preview layer the session without a connection, then connect it to this camera only.
        previewLayer.setSessionWithNoConnection(session)
        let connection = AVCaptureConnection(inputPort: videoPort, videoPreviewLayer: previewLayer)
        guard session.canAddConnection(connection) else {
            throw CameraError.addOutputFailed
        }
        session.addConnection(connection)
        
        return input
    }
```

### Step
After `addConnection`, set the mirroring of the connection by the position of the camera, and give it the rotation angle of the preview.

A connection that you make gets no automatic settings. Without this code, the front preview is not a mirror image, and both previews can be on their side. The order of the two mirroring assignments is the rule from chapter 16: [`isVideoMirrored`](https://developer.apple.com/documentation/avfoundation/avcaptureconnection/isvideomirrored) raises an exception while [`automaticallyAdjustsVideoMirroring`](https://developer.apple.com/documentation/avfoundation/avcaptureconnection/automaticallyadjustsvideomirroring) is `true`. The rotation coordinator is the class from chapter 2, now for a second camera and a second layer.

```swift file=AVCam/Capture/MultiCamCapture.swift highlight=3-10
        session.addConnection(connection)
        
        // A connection that the app creates gets no automatic settings. Mirror the front camera only,
        // as a person expects from a selfie, and turn the picture upright for the current orientation.
        if connection.isVideoMirroringSupported {
            connection.automaticallyAdjustsVideoMirroring = false
            connection.isVideoMirrored = device.position == .front
        }
        let rotationCoordinator = AVCaptureDevice.RotationCoordinator(device: device, previewLayer: previewLayer)
        connection.videoRotationAngle = rotationCoordinator.videoRotationAngleForHorizonLevelPreview
        
        return input
    }
```

### Step
Below `addCamera`, add the `selectMultiCamFormat(for:)` method. It sets the largest multi-camera format up to the width limit.

A multi-camera session uses no preset, so each camera keeps its active format. Only a format with [`isMultiCamSupported`](https://developer.apple.com/documentation/avfoundation/avcapturedevice/format/ismulticamsupported) works. The method keeps the active format when it fits. Else it takes the widest format up to 1920 pixels, and among equal widths the one with the highest frame rate. `maxFrameRate` is the extension from chapter 9. A change of the format needs the configuration lock of the device.

```swift file=AVCam/Capture/MultiCamCapture.swift highlight=4-22
        return input
    }
    
    /// Selects the largest format of the device that supports multi-camera capture, up to the width limit.
    private func selectMultiCamFormat(for device: AVCaptureDevice) throws {
        // Keep the active format if it already fits.
        if device.activeFormat.isMultiCamSupported && device.activeFormat.formatDescription.dimensions.width <= maxFormatWidth {
            return
        }
        let candidates = device.formats.filter {
            $0.isMultiCamSupported && $0.formatDescription.dimensions.width <= maxFormatWidth
        }
        // Prefer the widest format, and among equal widths the one with the highest frame rate.
        guard let format = candidates.max(by: {
            ($0.formatDescription.dimensions.width, $0.maxFrameRate) < ($1.formatDescription.dimensions.width, $1.maxFrameRate)
        }) else {
            throw CameraError.setupFailed
        }
        try device.lockForConfiguration()
        device.activeFormat = format
        device.unlockForConfiguration()
    }
}
```

## Build the dual preview view

The dual mode needs two preview views, one for each camera. In this section, you build the view that hosts them: a SwiftUI view, a `UIViewRepresentable`, and a container view that lays out the two previews. The view gets its layers from a source, as `CameraPreview` does. The source is a protocol here. Its implementation comes with the capture service in the next sections.

### Step
In `CameraPreview.swift`, add the `previewLayer` requirement to the `PreviewTarget` protocol, and add the `DualPreviewSource` protocol below it.

`PreviewView` already has a `previewLayer` property, so it conforms with no change. The requirement is on the main actor, because a layer belongs to a view. `DualPreviewSource` is the twin of `PreviewSource` from chapter 1, with two targets instead of one.

```swift file=AVCam/Views/CameraPreview.swift highlight=4-6,8-12
protocol PreviewTarget {
    // Sets the capture session on the destination.
    func setSession(_ session: AVCaptureSession)
    // The layer that presents the captured content.
    @MainActor var previewLayer: AVCaptureVideoPreviewLayer { get }
}

/// A protocol that connects the two preview views of the dual mode with the multi-camera session.
protocol DualPreviewSource: Sendable {
    // Connects the preview views for the back camera and the front camera to this source.
    @MainActor func connect(back: PreviewTarget, front: PreviewTarget)
}

/// The app's default `PreviewSource` implementation.
```

### Step
Below the initializers, add `layoutSubviews()` and the `layoutPreviews()` method. One preview gets the full bounds, and the other preview gets a corner.

UIKit calls `layoutSubviews()` after each change of the size, and the animation calls `layoutPreviews()` after each tap. The small picture has the same proportions as the view, at 30 percent of the width. It sits below the top safe area inset, with an inset of 16 points. `bringSubviewToFront` draws it on top of the full picture.

```swift file=AVCam/Views/DualCameraPreview.swift highlight=5-25
        required init?(coder: NSCoder) {
            fatalError("init(coder:) has not been implemented")
        }
        
        override func layoutSubviews() {
            super.layoutSubviews()
            layoutPreviews()
        }
        
        // Gives one preview the full bounds and the other preview a corner.
        private func layoutPreviews() {
            let small = smallPicture == .front ? frontPreview : backPreview
            let full = smallPicture == .front ? backPreview : frontPreview
            let width = bounds.width * smallPictureScale
            let height = width * bounds.height / max(bounds.width, 1)
            full.frame = bounds
            full.layer.cornerRadius = 0
            full.layer.borderWidth = 0
            small.frame = CGRect(x: inset, y: safeAreaInsets.top + inset, width: width, height: height)
            small.layer.cornerRadius = 12
            small.layer.borderWidth = 1
            // Draw the small picture on top of the full picture.
            bringSubviewToFront(small)
        }
    }
}
```

### Step
Below that method, add the `startDualCaptureIfNeeded()` method. It needs the dual mode, the two layers, and a device with support.

Two events can come in either order: the mode becomes dual, and the preview view appears. Both call this method, and the `guard` statement waits until both have occurred. The cameras come from the device lookup of chapter 2: the first back camera and the first front camera. `configure` runs its work one time only, so a second call after a change of the mode costs nothing. A configuration error goes to the log, and the dual mode stays black. The costs are the numbers from the concept page. A shipping app reduces the formats when a cost is above 1.0. This app only shows them.

```swift file=AVCam/CaptureService.swift highlight=6-24
    func attachDualPreview(back: AVCaptureVideoPreviewLayer, front: AVCaptureVideoPreviewLayer) {
        dualPreviewLayers = (back, front)
        startDualCaptureIfNeeded()
    }
    
    /// Configures and starts the multi-camera session when the dual mode is active and the preview layers exist.
    private func startDualCaptureIfNeeded() {
        guard captureMode == .dual, let layers = dualPreviewLayers, MultiCamCapture.isSupported else { return }
        let cameras = deviceLookup.cameras
        guard let backCamera = cameras.first(where: { $0.position == .back }),
              let frontCamera = cameras.first(where: { $0.position == .front }) else {
            logger.error("The dual mode needs a back camera and a front camera.")
            return
        }
        do {
            try multiCamCapture.configure(backCamera: backCamera, frontCamera: frontCamera,
                                          backPreview: layers.back, frontPreview: layers.front)
        } catch {
            logger.error("Unable to configure the multi-camera session: \(error)")
            return
        }
        multiCamCapture.start()
        logger.info("Dual capture costs: hardware \(self.multiCamCapture.hardwareCost), system pressure \(self.multiCamCapture.systemPressureCost)")
    }
    
    // MARK: - Device selection
```

## Connect the preview views to the service

The view exists, and the service runs the multi-camera session. In this section, you connect the two ends: the implementation of `DualPreviewSource`, a property of the capture service, two requirements in the `Camera` protocol, and their implementation in the two models.

### Step
Below the protocol, add the `DefaultDualPreviewSource` structure. It reads the two layers and gives them to the capture service in a task.

`DefaultPreviewSource` from chapter 1 holds the session. This structure holds the service, because the service owns the multi-camera session and connects the layers itself. The two layers are read on the main actor, and the task sends them to the capture actor. The preview layer class is `Sendable` in the SDK, so the compiler accepts this.

```swift file=AVCam/Views/CameraPreview.swift highlight=6-21
protocol DualPreviewSource: Sendable {
    // Connects the preview views for the back camera and the front camera to this source.
    @MainActor func connect(back: PreviewTarget, front: PreviewTarget)
}

/// The app's default `DualPreviewSource` implementation.
struct DefaultDualPreviewSource: DualPreviewSource {
    
    private let captureService: CaptureService
    
    init(captureService: CaptureService) {
        self.captureService = captureService
    }
    
    @MainActor
    func connect(back: PreviewTarget, front: PreviewTarget) {
        let backLayer = back.previewLayer
        let frontLayer = front.previewLayer
        // The capture service connects the layers on its own queue.
        Task { await captureService.attachDualPreview(back: backLayer, front: frontLayer) }
    }
}

/// The app's default `PreviewSource` implementation.
```

## Check your understanding

### `addCamera(_:previewLayer:)` calls `addInputWithNoConnections(_:)` and makes the connection to the preview layer itself. What would occur with a plain `addInput(_:)`?

- [ ] The session would refuse the input, because a multi-camera session accepts only inputs without connections.
  > A multi-camera session accepts both methods. The difference is what the session does after the input is added.
- [x] The session would connect the camera to every output and preview layer that accepts video, so the two cameras would not have their own preview.
  > Correct. The automatic connections are for one camera. With two cameras, the app must say which port goes to which layer, so it adds the input with no connections and creates one connection itself.
- [ ] The camera would keep a format that is not a multi-camera format.
  > The format selection runs before the input is created, with both methods. It is a separate requirement.

### The first test of the dual mode showed the front picture without mirroring. Which line fixes that, and why does the single preview not need it?

- [ ] `previewLayer.setSessionWithNoConnection(session)`. The single preview sets `session` instead, which mirrors the front camera.
  > This call gives the layer its session. It sets no mirroring. The single preview gets its mirroring from its connection, not from the session.
- [x] `connection.isVideoMirrored = device.position == .front`. The single preview has a connection that the session made, and such a connection mirrors the front position by itself.
  > Correct. A connection that the app makes has no automatic settings. The app sets `automaticallyAdjustsVideoMirroring` to `false` first, then `isVideoMirrored` by the position, and it also sets the rotation angle.
- [ ] `preview.previewLayer.videoGravity = .resizeAspectFill`. The single preview uses `resizeAspect`.
  > The video gravity decides how the picture fills the layer. It does not mirror the picture.

### A person leaves the dual mode for the video mode. In which order do the sessions change?

- [ ] The single-camera session starts first, so that the preview shows frames at once, and then the multi-camera session stops.
  > Two sessions cannot run at the same time. The start would fail while the multi-camera session has the cameras.
- [x] The multi-camera session stops, the single-camera session gets its video configuration, and the `defer` block starts it after the commit.
  > Correct. `setCaptureMode(_:)` stops the multi-camera session before `beginConfiguration()`, and the `defer` block calls `startRunning()` after `commitConfiguration()`, when the preset and the movie output are in place.
- [ ] The multi-camera session continues, and the single-camera session takes the back camera from it.
  > The two sessions do not share a camera. The service stops the multi-camera session with `multiCamCapture.stop()` before the single-camera session starts again.
