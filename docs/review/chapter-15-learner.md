Date: 15 Oct 2026

## Method

The same two personas as in the reviews of chapters 2 to 14 went through all 28 steps.

- **The copier** reads the code card and the delete boxes, pastes the highlighted lines at the place the fence shows, and builds at each checkpoint. Checked: is the place clear, is anything needed that no step says (import, Xcode action, deletion), do the delete boxes cover every line that `git diff chapter-14 chapter-15` removes or changes, is any line highlighted in two steps, does a highlighted run contain a line that already exists on `chapter-14`.
- **The self-implementer** uses the "Try first" mode. This person sees the instruction, the caption, the cover (file, "Inside …", context lines, placeholders, the comment lines of the solution as hints, delete box), and the Swift notes, but not the code. Checked: does the text give each new identifier with its type, access level, start value, `async`, and parameters; does it name each API (`AsyncStream`, `makeStream(of:bufferingPolicy:)`, `yield(_:)`, `Result`, `resume(with:)`, `resume(throwing:)`, `AVErrorRecordingSuccessfullyFinishedKey`, `addOutput(_:)`, `videoRotationAngleForHorizonLevelCapture`, `play(_:)`); does it say when the project does not compile or builds with warnings between steps.

The cover text of each of the 19 code steps was extracted from the rendered HTML (17 "Inside …" texts; the cover at file level, 1.1, has none, and 6.1 has no cover because its fence has no `highlight=`) and compared with `git diff chapter-14 chapter-15`. The findings were fixed on the page in the same pass (captions only; no instruction, main code fence, `remove` fence, or `copy` mark changed, because the chapter has no new file and no boilerplate). Then `npm run validate` and the replay ran.

## Suggestions for the generator and the glossary

1. **Glossary: `Result`.** The chapter uses `Result<Movie, Error>`, `.success`, `.failure`, `result.get()`, and `resume(with:)`. No entry matches. Suggested entry: pattern `/\bResult<[^>]+>/`, title "Result", text: "A value that is a success with a value or a failure with an error. `get()` returns the value or throws the error." Link: the Swift standard library page for `Result`.
2. **Glossary: a `let` without a value.** Step 2.2 declares `let result: Result<Movie, Error>` and sets it in each branch. The caption explains it now; an entry (pattern `/^\s*let \w+: [^=\n]+$/m`, title "let without a value", text: "A constant can get its value later, in each branch of an `if` or `switch`, as long as each path sets it exactly one time.") would make the sentence unnecessary in later chapters.
3. **Glossary: `Type.self` and `as NSError`.** Step 1.3 passes `Result<Movie, Error>.self` as a metatype, and 2.1 casts an `Error` to `NSError` to read `userInfo`. Neither has an entry. Both are short: pattern `/\.self\b/` (not `common`, because the first use in the tutorial may be here) and pattern `/as NSError\b/`.
4. **Generator: a parameter or local constant that hides a property.** Finding 2 (the local `delegate` hides `self.delegate` inside the closure) is the same class as suggestion 1 of the chapter 14 review (a constant that hides a parameter). The cover could show "Note: `delegate` here is the local constant of the method; the property needs `self.`" when a highlighted line writes `self.<name>` and a local `let <name>` is in the context lines above.
5. **Generator: a deletion-only step.** Step 6.1 has a fence without `highlight=`, so the "Try first" mode shows its code with no cover. This is correct, because the step adds nothing, but the cover sentence "Write this step yourself first" is also missing, so the mode switch looks broken at this one step. A short cover ("This step only deletes lines. See the delete boxes.") would keep the rhythm.
6. **Generator: a warning after a step.** Steps 2.2, 2.4, and 3.3 leave a warning (an unused `result`, an unused `self`, an unused loop variable) until the next step. As suggested in the reviews of chapters 9, 12, and 14, a fence attribute such as `warnings` would render a standard note instead of a caption sentence.
