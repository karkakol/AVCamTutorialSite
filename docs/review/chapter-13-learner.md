# Chapter 13 build page: learner review

Date: 15 Oct 2026
Page: `content/pages/ch13-build.md` (51 steps in 6 sections: 36 code steps and 15 Xcode steps with `settings` fences, of which 2 are checkpoints), rendered as `dist/ch13-build.html` after `node src/build.mjs`.

## Method

The same two personas as in the reviews of chapters 2 to 12 went through all 51 steps.

- **The copier** reads the code card and the delete boxes, pastes the highlighted lines at the place the fence shows, and builds at each checkpoint. Checked: is the place clear, is anything needed that no step says (import, Xcode action, deletion, target membership), do the delete boxes cover every line that `git diff chapter-12 chapter-13` removes or moves, is any line highlighted in two steps, does a highlighted run contain a line that already exists on `chapter-12`. For the 15 Xcode steps: does each name the exact menu, template, option, target name, and value, and do the two target membership steps list every file that the `membershipExceptions` lists of the project file on `chapter-13` contain.
- **The self-implementer** uses the "Try first" mode. This person sees the instruction, the caption, the cover (file, "Inside …", context lines, placeholders, the comment lines of the solution as hints, delete box), and the Swift notes, but not the code. Checked: does the text give each new identifier with its type, access level, start value, `async`/`throws`, and parameters; does it name each API type and modifier with its arguments; does it give the string values (log texts, titles, the `kind` string, the symbol name); does it say when the project does not build between steps.

The 36 cover texts were extracted from the rendered HTML (28 "Inside …" texts; 5 covers at file level and 3 covers at top level have none) and compared with `git diff chapter-12 chapter-13` and `git show chapter-13:<file>`. The 29 shared files were counted with `git ls-tree` on `chapter-13` and compared with the exception list of the capture extension target. The findings were fixed on the page in the same pass (captions, two Notes, two counts, one alt text; no instruction, main code fence, `remove` fence, or `copy` mark changed). Then `npm run validate` and the replay ran.

## Suggestions for the generator and the glossary

1. **Generator: string literals on the cover.** Findings 1, 4, 5, 8, and 13 are string values (a `kind` string, a symbol name, titles, log texts) that only the solution shows. The cover shows comment lines as hints; it could also list the string literals of the highlighted lines ("the step uses the strings: …"), as suggestion 3 of the chapter 12 review says.
2. **Generator: a replaced template file.** Steps 5.4, 6.3, and 6.5 replace the contents of a file that Xcode created. The cover says "create the new file … and write the whole file yourself" for a fence with `highlight=1-N` or `new`. A fence attribute such as `replace` would render "replace the contents of … (the file exists)".
3. **Generator: a step that breaks the build of a dependent target.** Findings 7, 9, and 10 are "does not build until step X" sentences. A fence attribute such as `compiles=no` (chapter 9 review, suggestion 2; chapter 12 review, suggestion 2) would render a standard note.
4. **Validator: the counts in the text.** Finding 2 is a wrong file count in a settings row and in the diagram. A validator cannot check prose, but a note in `npm run validate -- --budget` with the number of Swift files per folder on `branch` would give the writer the number.
5. **Diagram `content/images/ch13-targets.svg`.** The title and the text "25 files: the model, the capture service, and the views" must say 26 (29 shared files, of which 3 are in all targets). This review did not change the SVG, because the scope was the page. The alt text on the page says 26 now.
6. **Replay: section 2.** The replay prints `claims=n build=FAILS` for section 2, because the section ends with a Note that says that the project does not compile (`CameraModel` still calls `start()`). The replay is correct, and the page claims no build there.
