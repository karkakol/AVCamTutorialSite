## Method

The same two personas as in the reviews of chapters 2 to 14 went through all 40 steps.

- **The copier** reads the code card and the delete boxes, pastes the highlighted lines at the place the fence shows, and builds at each checkpoint. Checked: is the place clear, is anything needed that no step says (import, Xcode action, deletion), do the two delete boxes cover the two lines that `git diff chapter-15 chapter-16` removes, is any line highlighted in two steps, does a highlighted run contain a line that already exists on `chapter-15`.
- **The self-implementer** uses the "Try first" mode. This person sees the instruction, the caption, the cover (file, "Inside …", context lines, placeholders, the comment lines and the string literals of the solution as hints, delete box), and the Swift notes, but not the code. Checked: does the text give each new identifier with its type, access level, start value, `async`, `@escaping`, and parameters; does it name the AVKit API (`AVCaptureDeviceDirectionCoordinator`, `init(view:deviceTypes:changeHandler:)`, `AVCaptureDeviceDirectionMap` with `forwardFacingDeviceDescriptors` and `backwardFacingDeviceDescriptors`, `AVCaptureDeviceDescriptor` with `uniqueID`), the device types (`.builtInOuterUltraWideCamera`, `.builtInInnerUltraWideCamera`, and the five existing types), the `#available(iOS 27.1, *)` checks, the mirroring API (`isVideoMirroringSupported`, `automaticallyAdjustsVideoMirroring`, `isVideoMirrored`), and the layout modifiers with their values (`onGeometryChange(for: CGFloat.self)` with `action:`, `ignoresSafeArea(.container, edges: .horizontal)`, `padding(.horizontal, sideInsetDifference / 2)`); does it say when the project does not compile or builds with warnings between steps.

The cover text of each of the 33 code steps was extracted from the rendered HTML (31 "Inside …" texts; the covers of 2.1 and 3.1 are at file level and have none) and compared with `git diff chapter-15 chapter-16 -- '*.swift'` and `git show chapter-16:AVCam/CaptureService.swift`. The findings were fixed on the page in the same pass (captions only; no instruction, main code fence, `remove` fence, or `copy` mark changed, because the chapter has no new file and no boilerplate). Then `npm run validate` and the replay ran.

## Suggestions for the generator and the glossary

1. **Glossary: `MainActor.assumeIsolated`.** Step 3.5 uses it, and no entry matches. Suggested entry: pattern `/MainActor\.assumeIsolated\s*\{/`, title "MainActor.assumeIsolated", text: "Tells the compiler that this code already runs on the main actor. The closure can then call main-actor code with no `await`. The program stops if the code runs somewhere else." Link: the documentation page that 3.5 links.
2. **Glossary: a stored property of type `AnyObject` for a class that needs a newer system.** Step 3.2 uses the pattern, and the caption explains it. It is not a Swift keyword, so a glossary entry is optional; a note in `AUTHORING.md` under "Writing style" would tell the next writer to explain it the same way.
3. **Glossary: a synchronous method for an `async` requirement.** Step 6.3 is the same pattern as chapter 14, step 4.8 (suggestion 2 of that review). The caption now says it; one entry would serve both pages.
4. **Generator: a step that breaks the build.** This page has three places (2.4, 4.2, 6.1) where the project does not compile until a later step, and four places with warnings (2.2, 5.1, 5.2, 5.3). The `compiles=no` or `warnings` fence attribute from the chapter 9, 12, and 14 reviews would render a standard note instead of a caption sentence in each place.
5. **Generator: argument labels.** Finding 1 is an argument label (`onDirectionsChange`) that only the solution shows. The cover shows comments and strings as hints. It could also list the argument labels of a new initializer or method signature in the highlighted lines ("labels in this code: `onDirectionsChange`"), in the same hint style.
6. **Generator: a highlighted `} else {` that replaces a closing brace.** Step 5.5 highlights `} else {` where the copier has a `}` from 4.5. The validator and the replay accept it, but the copier gets no delete box. A `remove` fence with one `}` would be noise; a generated hint ("this line replaces the closing brace of the `if`") when a highlighted line starts with `}` and the previous step highlighted a plain `}` at that place would be better.
7. **Replay: the `claims` flag.** All six sections print `claims=Y`, so the Experiment, Note, and Text items after the last checkpoint of section 6 do not disturb the flag on this page.
