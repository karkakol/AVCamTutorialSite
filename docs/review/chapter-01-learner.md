# Chapter 1 build page: learner review

Date: 14 Oct 2026
Page: `content/pages/ch01-build.md` (46 steps in 6 sections), rendered as `dist/ch01-build.html` after `node src/build.mjs`.

## Method

The same two personas as in the chapter 2 and 3 reviews went through all 46 steps.

- **The copier** reads the code card and the delete boxes, pastes the highlighted lines at the place the fence shows, and builds at each checkpoint. Checked: is the place clear, is anything needed that no step says (group, file, import, Xcode action, deletion), do the delete boxes cover every line that `git diff start chapter-01` removes or moves. Chapter 1 also has seven Xcode steps (template, deployment target, three concurrency build settings, two Info.plist values, run) and one delete step. For each, the exact place in Xcode and the exact value were compared with the project file diff (`AVCam.xcodeproj/project.pbxproj`).
- **The self-implementer** uses the "Try first" mode. This person sees the instruction, the caption, the cover (file, "Inside …", context lines, placeholder), and the Swift notes, but not the code. Checked: does the text give each new identifier with its type, access level, `async`/`throws`, and parameters; does it name each API that the solution calls; do boilerplate steps carry the `copy` mark and a spec; do captions for views give sizes, colors, and symbols. Chapter 1 is the first page, so every Swift note card was checked for its text and its placement.

The cover text, the place lines, and the Swift note cards of each step were extracted from the rendered HTML and compared with `git show chapter-01:<file>`. The findings were fixed on the page in the same pass. Then `npm run validate` and the replay ran.

## Suggestions for the generator or the glossary

1. **Generator: fewer cards on one step.** When `closure-isolation` (`Task { @MainActor in }`) matches a step, suppress the `task` and `main-actor` cards on the same step; the one card covers both. Step 2.9 then shows two cards instead of four.
2. **Glossary: `nonisolated` text.** Change "A member of an actor" to "A member of an actor, or of a type on the main actor such as a view". The first use (2.9) is on a `UIView` subclass.
3. **Glossary gaps on this page:** `@discardableResult` (4.3), `private(set)` (5.5), the forced cast `as!` (2.8), `override class var` (2.8), `required init?(coder:)` with `fatalError` (2.7), `@main` (6.4). `private(set)` and `@discardableResult` repeat in every later chapter; one `common` entry each is enough.
4. **Validator: a highlighted line that a later step highlights again.** Finding 3 (6.2 and 6.3) is a page error that the validator cannot see, because coverage only asks that each added line is highlighted at least once. A warning "line N of file F is highlighted in steps 6.2 and 6.3" would catch it.
5. **Generator: context for a "create the file" step with a note.** Step 6.2 creates a file that does not compile until 6.3. The caption says so now, but a generator feature that lets a step say "does not compile yet" (as the `### Note` after a step does) in the cover would help the self-implementer who builds after each step.
